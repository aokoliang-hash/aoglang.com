aoglang 站点 SEO 复盘：从薄内容到专题化静态站

2026-06-16 · English

aoglang 是一个纯 HTML 双语静态站，曾面临 Google AdSense「低价值内容」拒审。2026 年 6 月我们进行了一轮系统性 SEO 改造：以深度专题替代批量薄页、精简 sitemap、强化 E-E-A-T。本文记录改造前后策略、技术实现与Google Search Console 操作步骤，供同类站点参考。

改造前的问题诊断

拒审原因可归纳为：① 50+ 张结构相同的单图页（每张仅 100 字模板文案）；② 深度文章不足 10 篇且偏短；③ 关于页过于简略，缺乏作者/编辑信息；④ 站点在短时间内大量上新，呈现「程序化 SEO」特征。技术 SEO（sitemap、hreflang、canonical）虽已就绪，但内容价值未达标。

核心策略：专题优先 + 薄页 noindex

我们在 tools/build.mjs 中引入 INDEXABLE_PICTURE_SLUGS：仅 8 张航拍旗舰单图保留索引，其余单图页输出 <meta name="robots" content="noindex, follow">，搜索权重集中于 东京航拍完全指南、人物商务手册 等 15+ 篇专题。sitemap 从 280+ URL 精简至文章 + 合辑 + 旗舰图。

E-E-A-T 与信任页

扩充关于我们（站点定位、内容标准、与 aogl.cn 关系）；更新隐私政策（Analytics、AdSense Cookie 说明）；文章底部自动添加作者署名与 BlogPosting schema。联系表单指向真实邮箱 hello@aoglang.com。

技术 SEO 清单（已实现）

双语独立 URL + hreflang；根目录 robots.txt 指向 sitemap.xml；每页 canonical、Open Graph、JSON-LD（WebSite、BlogPosting、ImageObject、VideoObject）；RSS（zh/feed.xml）；站内搜索索引（assets/data/search-index.json）；ads.txt 置于根目录。

Google Search Console 配置步骤

① 访问 Google Search Console，添加资源「网址前缀」https://aoglang.com；② 用 DNS TXT 或 HTML 文件验证所有权；③ 左侧「站点地图」→ 输入 sitemap.xml → 提交；④ 使用「网址检查」测试首页与 2–3 篇专题是否「可编入索引」；⑤ 每周查看「网页编制索引」与「体验」→ Core Web Vitals。

部署后通知搜索引擎

每次重大更新并部署后，在项目根目录执行：npm run ping-sitemap（向 Google ping sitemap，见 tools/ping-sitemap.mjs）。Bing 需在其 Webmaster Tools 手动提交。

Bing Webmaster 与其他渠道

同步注册 Bing Webmaster Tools 并提交同一 sitemap。可在 GitHub README、RSS 阅读器、摄影社区分享专题文章链接（而非单图薄页），获取自然外链。

内容持续更新建议

AdSense 复审前建议：深度专题 ≥ 15 篇（已完成）；每周 1 篇 1200 字以上新文；2–3 个月自然搜索展示逐步上升；避免恢复批量单图 SEO 页。内容矩阵：航拍（东京、福州/风电）、3D（无穷符号）、视频（短片合集）、工业（科技工业）。

AdSense 复审 checklist

□ ads.txt 已授权 □ 关于/联系/隐私完整 □ 深度原创内容充足 □ 薄页已 noindex □ Search Console 无大量抓取错误 □ 改造后持续更新 2–3 个月 □ 勾选「已解决低价值内容」后再申请。
